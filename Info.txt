Architecture actuelle — état réel du code
Ce qui est construit et compilé
1. Bridge C# — production/bridge/Program.cs

Exécutable MesHaiBridge.exe qui :

Reçoit un JSON sur stdin
Charge MES_HAI.dll par réflexion .NET
Appelle la méthode MES demandée (Login, Serial_GetInformation, Serial_MoveIn, Serial_MoveOutAndTestResults)
Retourne un JSON sur stdout avec ok, result, errorDetail (ErrorCode + ErrorDescription)
Actions supportées :


login | get-info | move-in | move-out | move-out-and-test
2. Orchestrateur Node.js — production/orchestrator/mes-orchestrator.js

Serveur HTTP local (port 7070) avec les endpoints :

Méthode	Route	Description
GET	/health	Santé + statut login
POST	/v1/login	Login MES
POST	/v1/get-info	Info série
POST	/v1/move-in	Flux complet : login → get-info → move-in
POST	/v1/move-out-and-test	MoveOut + résultats de test
POST	/v1/bridge	Appel direct bridge (raw)
3. Configuration — production/config/client-config.template.json

Chemins de déploiement cible sur le PC client :


C:\MESApps\ClientGateway\bridge\MesHaiBridge.exe
C:\MESApps\ClientGateway\bridge\MES_HAI.dll
C:\ProgramData\MESApps\CIM\MES_HAI.xml
4. Test local — production/client-install-test/config/client-config.json

Même orchestrateur mais pointant sur les fichiers locaux du dossier embarque pour valider avant déploiement machine.
